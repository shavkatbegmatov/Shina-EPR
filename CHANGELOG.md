### Security
- **Vaqtinchalik parolli xodim tizimga kira olmasdi.** `mustChangePassword` qorovuli yo'lni context-path'siz (`/v1/...`) solishtirardi, prodda esa URI `/api/v1/...` — parol almashtirish endpointi ham 403 olardi. Testlar buni ko'rmasdi (mock so'rovda context-path yo'q).
- **Prodda OpenAPI ochiq edi.** `/api/api-docs` autentifikatsiyasiz barcha endpointlar va DTO'larni qaytarardi; prod profilida springdoc o'chirildi, `/actuator/**` faqat `health` bilan cheklandi.
- **Yuklangan fayl kengaytmasi mijoz bergan nomdan olinardi** — `image/png` deb yuborilgan `x.html` `/api/uploads/` dan HTML sifatida xizmat qilinardi (stored XSS). Endi tur faqat magic bytes'dan.
- **Refresh token URL parametrida** (proksi loglariga tushardi) → JSON body; refresh endpointiga IP throttle. **Parallel refresh** reuse-detection'ni chetlab o'tardi → bitta tranzaksiya + `FOR UPDATE`. Access token muddati 24 soatdan 30 daqiqaga.
- **Buyurtma raqamlari taxminlanadigan** (`currentTimeMillis`) edi va ommaviy `/status`, `/pay` egalik tekshirmasdi → tasodifiy 2^40 raqam + rate limit.
- **nginx xavfsizlik sarlavhalari** (CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy); do'kon `?redirect=` ochiq redirect yopildi; `application-dev.yml` dagi haqiqiy DB paroli `.env` ga ko'chdi (tarixda qolgan — almashtiring).
- Sinf darajasidagi `@RequiresPermission` ishlamasdi (pointcut faqat metod) — endi `@within` ham.
- **npm:** 26 zaiflik (2 critical) → diapazon ichida yangilash, xlsx SheetJS CDN build'i (0.20.3); backend: o'lik `modelmapper`/`commons-lang3`/`logstash`/`spring-cloud-vault` olib tashlandi, Boot 3.5.16, POI 5.5.1.
- **Refresh token endi sessiyaga bog'landi va har chaqiruvda rotatsiya qilinadi.** Ilgari refresh token sessiyadan mustaqil edi: logout, admin tomonidan sessiyani bekor qilish, parol almashtirish yoki xodimni deaktivatsiya qilish **refresh tokenni o'ldirmasdi** — ishdan bo'shatilgan xodim 24 soatgacha to'liq ERP kirishini saqlab qolardi. Endi sessiya qatori refresh token hashini ham saqlaydi (`refresh_token_hash` + `previous_refresh_token_hash`, V41), refresh faqat tirik sessiya bilan ishlaydi, va rotatsiyadan chiqqan eski token qayta kelsa **butun sessiya yopiladi** (o'g'irlangan token belgisi). Sessiyaning mutlaq muddati bor — kunda bir yangilab turgan qurilma abadiy kirishda qolmaydi. **Ta'siri: yangilanishdan keyin barcha xodimlar bir marta qayta kiradi.**
- **`mustChangePassword` endi serverda majburlanadi.** Tekshiruv faqat frontendda edi, ya'ni vaqtinchalik parol bergan xodim oynani yopib yoki API'ga to'g'ridan-to'g'ri murojaat qilib ishlashda davom eta olardi. Endi `JwtAuthenticationFilter` parol almashtirilmaguncha `change-password`/`me`/`logout`/`refresh-token` dan boshqa hamma narsani 403 bilan rad etadi.
- **Refresh token access token o'rnida ishlatilishi to'sildi.** Filtr token turini ajratmasdi — uzoq muddatli refresh token oddiy so'rovlarda ham o'tardi. Deaktivatsiya qilingan foydalanuvchi tekshiruvi (`isEnabled`) ham qo'shildi.
- **Ommaviy seed parollari zararsizlantirildi.** `V2`/`V3` (`admin/admin123`, `seller/seller123`) va `V6` (test mijoz, PIN `1234`) `db/migration` ichida bo'lgani uchun production bazasiga ham tushardi, hash'lar esa repoda ochiq. `V29` test mijoz portalini o'chiradi; `DefaultCredentialGuard` (dev'dan tashqari) ishga tushishda parol hali standart ekanini `matches()` bilan tekshirib almashtiradi. Yangi parol `ADMIN_INITIAL_PASSWORD` dan olinadi, bo'lmasa tasodifiy generatsiya qilinib logga bir marta yoziladi (akkaunt bloklanmaydi — egasi qulflanib qolmasligi uchun).
- **To'lov webhook'lari fail-closed qilindi.** Click `complete` `enabled`ni tekshirmasdi va `secretKey` defaulti bo'sh edi — bo'sh kalitda MD5 imzo faqat ommaviy maydonlardan hisoblanardi, ya'ni begona odam buyurtmani to'lamasdan `PAID` qila olardi. Endi o'chiq integratsiya/bo'sh kalit rad etiladi, `complete`ga summa tekshiruvi qo'shildi, takroriy chaqiruv idempotent, imzo doimiy-vaqtda solishtiriladi. Payme'ga ham `enabled` tekshiruvi qo'shildi va istisno matni endi provayderga qaytarilmaydi.
- **Qarz va dashboard endpointlariga avtorizatsiya qo'shildi.** `DebtController`ning 13 endpointidan faqat `/export` himoyalangan edi — jumladan `POST /{id}/pay` va `/pay-full` moliyaviy yozuvlari. `DASHBOARD_VIEW` ham backend'da tekshirilmasdi. `ControllerAuthorizationCoverageTest` bundan keyin annotatsiyasiz endpointda CI'ni yiqitadi.
- **JWT default kaliti olib tashlandi.** `application.yml`dagi `${JWT_SECRET:mS1mNCt...}` fail-open edi. Endi kalit berilmasa ilova ishga tushmaydi; `JwtTokenProvider` bo'sh, qisqa (<32 bayt), noto'g'ri base64 va eski sizib ketgan kalitni aniq xabar bilan rad etadi. Dev default `application-dev.yml`ga ko'chirildi.
- CI backend endi `mvnw clean test` bajaradi (ilgari `compile -DskipTests` edi) — yuqoridagi qorovul testlari aks holda hech qachon ishlamasdi.
- **Bildirishnomalarda egalik tekshiruvi (IDOR).** `markAsRead`/`deleteNotification` faqat mavjudlikni tekshirardi — istalgan xodim id'ni sinab boshqasining bildirishnomalarini o'chira olardi. Endi `user.id = :userId OR user IS NULL` sharti bilan scoping qilinadi (global bildirishnomalar xatti-harakati o'zgarmadi).

- **Mijoz login'ida enumeration yopildi.** Metod oltita farqli xabar qaytarardi ("portal yoqilmagan", "hisob faol emas", "PIN o'rnatilmagan", "bloklangan, N daqiqa", "qolgan urinishlar: N") va faqat bittasi raqam topilmaganda chiqardi — ya'ni javobning o'zi telefon raqam do'kon mijozimi yoki yo'qmi degan savolga aniq javob berardi. Endi akkaunt holati haqidagi aniq xabar **faqat PIN to'g'ri bo'lgandan keyin** beriladi; aks holda yagona umumiy xabar (qulflash siyosati bilan, shunda haqiqiy foydalanuvchi ogohlantirishni yo'qotmaydi). Raqam topilmaganda ham bcrypt bajariladi — javob vaqti enumeration kanaliga aylanmasin.
- **Login'da IP bo'yicha throttle.** Himoya faqat foydalanuvchi nomi bo'yicha edi (5 urinish / 30 daqiqa), ya'ni credential stuffing to'silmasdi: bitta parolni minglab turli login'ga sinab ko'rsa, hech bir akkaunt chegaraga yetmasdi. Endi xodim va mijoz login'lariga IP bo'yicha chegara (30 muvaffaqiyatsiz urinish / 15 daqiqa) qo'shildi. Faqat **muvaffaqiyatsiz** urinishlar hisoblanadi va muvaffaqiyatli kirish byudjetni tozalaydi — bitta ofis IP'si ortidagi xodimlar bloklanmaydi.
- **`X-Forwarded-For` spoofing yopildi.** `forward-headers-strategy: framework` `getRemoteAddr()` ni XFF ning **birinchi** (mijoz yuborgan) qiymatiga o'rnatardi — hujumchi har so'rovda soxta IP yozib throttle'ni butunlay chetlab o'ta olardi. `native` (Tomcat RemoteIpValve) ga o'tildi: u XFF ni o'ngdan chapga yurib ishonchli proksilarni o'tkazib yuboradi. Xatti-harakat `ClientIpTest`da o'lchangan.
- **`ResponseStatusException` statusi saqlanadi.** `@ExceptionHandler(Exception.class)` catch-all uni ham ushlab, **har qanday statusni 500 ga aylantirardi** — buyurtma endpointidagi mavjud rate-limit javobi (429) mijozga "Ichki server xatosi" bo'lib borardi.

### Performance
- **Vitrina boshlang'ich yuklamasi 1,9 MB → 0,95 MB.** `manualChunks` obyekt shakli jsPDF/xlsx chunk'ini entry'ga statik bog'lab qo'ygan edi; `lucide-react` dan butun ikonka to'plami import qilinardi (vendor-ui 361 → 115 KB); `ru` lug'ati endi lazy. Prod build'da `console.*` olib tashlanadi.
- **Har autentifikatsiyalangan so'rovda sessions jadvaliga UPDATE** — endi 5 daqiqada bir. API JSON javoblari siqiladi (`server.compression`).
- **Eksportda chegarasiz `maxRecords` yopildi.** 13 ta eksport endpointi `maxRecords` ni to'g'ridan-to'g'ri `PageRequest`ga uzatardi, yuqori chegarasiz — `?maxRecords=100000000` butun jadvalni xotiraga yuklab, undan Excel/PDF quriladi, ya'ni bitta so'rov ilovani OOM bilan yiqita olardi. Endi `ExportSupport` maksimal 50 000 qatorni talab qiladi (oshsa aniq 400, jimgina kesish emas), nol/manfiy qiymat ham 400 beradi (ilgari 500 edi). Chegara ichida bo'lsa ham natija to'liq bo'lmasa, `X-Export-Truncated` sarlavhasi va WARN log bildiradi.
- **Mijoz portali statistikasi.** `getDashboardStats` savdolar **sonini** olish uchun `Pageable.unpaged()` bilan mijozning barcha savdolarini yuklardi; endi `countByCustomerId`.
- **N+1 so'rovlar bartaraf etildi.** Ro'yxat endpointlarining barcha response mapper'lari LAZY assotsiatsiyalarga tegardi (`SaleResponse` → customer/createdBy/items/item.product, `DebtResponse` → customer/sale, `StockMovementResponse` → product/supplier/createdBy, `ProductResponse`/`CatalogProductResponse` → brand/category). Bundan tashqari `AuditEntityListener` har `@PostLoad`da `toAuditMap()` chaqiradi, u esa `items.size()` bilan kolleksiyalarni ishga tushirardi. Global `hibernate.default_batch_fetch_size: 50` va issiq ro'yxat so'rovlariga `@EntityGraph` qo'shildi. **O'lchangan: 20 qatorlik savdo sahifasi 104 → 6 ta so'rov**; so'rovlar soni endi qatorlar soniga qarab o'smaydi. Kolleksiyalar `@EntityGraph`ga ATAYLAB qo'shilmadi — `@OneToMany` + `Pageable` Hibernate'ni xotirada sahifalashga majbur qiladi (HHH000104).
